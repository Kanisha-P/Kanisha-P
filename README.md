# Featured Projects

<details>
<summary><strong>Marginalia — Personal Reading & Quote Resurfacing Platform</strong></summary>

<br>

A web application designed around the idea that the value of a highlighted passage is not just in capturing it, but in **re-encountering it later**. Marginalia randomly resurfaces quotes from a user's own collection whenever they log in, helping meaningful passages return instead of disappearing into an abandoned list.

| Category        | Details                                                                        |
| :-------------- | :----------------------------------------------------------------------------- |
| **Stack**       | Python · Flask · SQLite · Bootstrap · JavaScript · Chart.js                    |
| **Scale**       | Full-Stack Web Application                                                     |
| **Performance** | Live dashboards, search, filtering and database-backed content                 |
| **Security**    | Hashed passwords · Session-based authentication · Server-side ownership checks |
| **Impact**      | Helps readers revisit and reflect on previously saved passages                 |
| **Repository**  | GitHub                                                                         |

### Project Overview

Marginalia allows users to register accounts, log books they are reading, and attach quotes with page numbers, speakers, moods, favourites and personal reflections.

The application includes a **resurfacing homepage**, personal dashboard and charts, quote search and filtering, mood tagging, and an optional anonymous public feed where users can share individual quotes.

A major focus of the project is secure data ownership. Every write operation checks server-side that the requested record belongs to the logged-in user. The anonymous feed is also designed so that the database query itself does not retrieve identifying information about the person who shared a quote.

The project uses a Flask backend with SQLite and a Bootstrap, vanilla JavaScript and Chart.js frontend.

</details>

<summary><strong>AcadSync — University Course Registration System</strong></summary>

<br>

A school project developing a **role-based university course registration system** that models real academic constraints such as prerequisites, eligibility, scheduling conflicts, seat capacity and credit requirements.

| Category        | Details                                                             |
| :-------------- | :------------------------------------------------------------------ |
| **Stack**       | Python · Tkinter · JSON · MySQL                                     |
| **Scale**       | Grade 11 School Project · Grade 12 Extension Planned                |
| **Performance** | Constraint-based registration and scheduling checks                 |
| **Security**    | Hashed passwords · Role-based authentication                        |
| **Impact**      | Automates academic registration while enforcing institutional rules |
| **Repository**  | In Development                                                      |

### Project Overview

AcadSync is being developed as a course registration system for students and professors. The **Grade 11 version uses JSON-based data storage**, accessed through a single `data_access.py` module, with MySQL planned for the Grade 12 extension.

Students will be able to browse course offerings, register and drop courses, view their timetable and track credit progress. Professors will be able to create and edit course offerings and view enrolled students.

The core registration engine handles **year eligibility, major/minor eligibility, prerequisites, timing clashes, professor and room conflicts, seat capacity and credit tracking**. The same time-overlap logic is reused to prevent both student scheduling conflicts and professor/room double-booking.

The system is being designed around clear rejection messages so users understand why a registration or scheduling action cannot be completed.

### Grade 11 Scope

* Separate student and professor accounts
* Hashed password authentication
* Role-based interfaces
* Colleges, majors, minors and academic-year eligibility
* Course offerings with time slots, rooms, seat capacity and credits
* Prerequisite and eligibility verification
* Student timing-clash detection
* Professor and room double-booking prevention
* Course drop functionality with credit reversal
* Credit progress tracking
* Personal timetable
* JSON-based data layer
* Testing with sample student and professor accounts

### Grade 12 Planned Extension

* Migration from JSON to MySQL
* Automatic waitlist promotion
* Full offering requirements
* Admin dashboard
* Semester and add/drop deadline management
* Grade and transcript tracking
* Automatic visual timetable generation
* Registration and waitlist notifications
* SQL-based registration analytics
* Expanded multi-semester dataset and concurrent testing
